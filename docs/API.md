# XyntraPOS — API & Database Specification

This document provides a comprehensive reference for the Supabase Postgres schema, Row-Level Security (RLS) policies, RPC stored procedures, custom API services, and payment webhook integrations.

---

## 1. Database Schema Overview

XyntraPOS stores multi-tenant merchant data using strict relational boundaries grouped around `business_id`.

### Core Tables

#### `profiles`
Stores merchant user account details linked to Supabase `auth.users`.
- `id` (UUID, Primary Key, References `auth.users.id`)
- `full_name` (Text, Required)
- `role` (Text, Enum: `'owner'`, `'admin'`, `'cashier'`)
- `phone` (Text, Optional)
- `has_completed_tutorial` (Boolean, Default: `false`)
- `created_at` (TimestampTZ)
- `updated_at` (TimestampTZ)

#### `businesses`
Stores merchant business registration profile.
- `id` (UUID, Primary Key, Default: `gen_random_uuid()`)
- `owner_id` (UUID, Required, References `profiles.id`)
- `name` (Text, Required)
- `slug` (Text, Unique, Required)
- `currency` (Text, Default: `'NGN'`)
- `country` (Text, Default: `'Nigeria'`)
- `address` (Text, Optional)
- `phone` (Text, Optional)

#### `staff_members`
Tracks employee accounts and assigned permissions within a business.
- `id` (UUID, Primary Key)
- `business_id` (UUID, References `businesses.id`)
- `user_id` (UUID, References `profiles.id`)
- `role` (Text, Enum: `'admin'`, `'cashier'`, `'inventory_manager'`)
- `status` (Text, Enum: `'active'`, `'inactive'`, `'invited'`)
- `permissions` (JSONB)

#### `staff_invitations`
Stores secure pending invitation codes generated by business owners/admins.
- `id` (UUID, Primary Key)
- `business_id` (UUID, References `businesses.id`)
- `invitation_code` (Text, Unique, Required)
- `email` (Text, Optional)
- `role` (Text, Required)
- `status` (Text, Default: `'pending'`)
- `expires_at` (TimestampTZ)

#### `categories`
Product categories defined by a business.
- `id` (UUID, Primary Key)
- `business_id` (UUID, References `businesses.id`)
- `name` (Text, Required)
- `color` (Text, Optional)

#### `products`
Inventory catalog items.
- `id` (UUID, Primary Key)
- `business_id` (UUID, References `businesses.id`)
- `category_id` (UUID, References `categories.id`)
- `name` (Text, Required)
- `sku` (Text, Required)
- `barcode` (Text, Optional)
- `cost_price` (Numeric(12,2), Default: 0)
- `selling_price` (Numeric(12,2), Required)
- `stock_quantity` (Integer, Default: 0)
- `min_stock_alert` (Integer, Default: 5)
- `unit` (Text, Default: `'pcs'`)
- `is_active` (Boolean, Default: `true`)

#### `sales` & `sale_items`
Records completed checkout transactions and itemized line purchases.
- `sales`: `id`, `business_id`, `cashier_id`, `customer_id`, `total_amount`, `subtotal`, `discount_amount`, `tax_amount`, `payment_method`, `status`
- `sale_items`: `id`, `sale_id`, `product_id`, `quantity`, `unit_price`, `subtotal`, `discount`

#### `shifts`
Tracks active work shifts, cash drawer balances, and clock-in/out timestamps.
- `id` (UUID, Primary Key)
- `business_id` (UUID, References `businesses.id`)
- `staff_id` (UUID, References `staff_members.id`)
- `start_time` (TimestampTZ)
- `end_time` (TimestampTZ, Optional)
- `starting_cash` (Numeric(12,2))
- `ending_cash` (Numeric(12,2), Optional)
- `status` (Text, Enum: `'open'`, `'closed'`)

## 2. Row-Level Security (RLS) Policy Model

Multi-tenancy isolation is enforced at the database layer using Postgres RLS policies:

- **Business Isolation**: Users can only `SELECT`, `INSERT`, `UPDATE`, or `DELETE` records where `business_id` matches a business where they are the owner or an active staff member.
- **Staff Access Policies**: Cashiers cannot alter business settings or invite new staff members.
- **RPC Function Security**: Privileged operations (claiming staff invitations, updating stock levels on sale completion) are executed through `SECURITY DEFINER` functions with internal authorization checks.

---

## 3. Stored Procedures (RPC)

### `claim_staff_invitation(p_invitation_code TEXT)`
Calculates validity of invitation code, registers candidate user as an active staff member in `staff_members`, and updates invitation status to `'accepted'`.

### `process_sale_checkout(...)`
Atomic transaction function that creates `sales` & `sale_items` entries, updates `stock_quantity` on sold items, and updates active shift cash register totals in a single atomic SQL transaction.

## 4. Webhook Security Specification

### Paystack Payment Webhook
- **Endpoint**: `https://<domain>/api/webhooks/paystack`
- **Method**: `POST`
- **Header**: `x-paystack-signature`
- **Verification**: Compute HMAC SHA-512 of request payload using `PAYSTACK_SECRET_KEY` and compare with header.

```ts
import { verifyWebhookSignature } from '@xyntra/utils';

const isValid = await verifyWebhookSignature(
  rawBodyString,
  req.headers['x-paystack-signature'],
  process.env.PAYSTACK_SECRET_KEY
);
```
